## 完成内容

### 问题排查：移动端提取文件失败（PC正常）

**根因分析：** PDF.js v6 创建的是 Module Worker（`{type: "module"}`），移动端 Safari 对 Module Worker 的 MIME 类型检查非常严格。`new URL("pdfjs-dist/build/pdf.worker.min.mjs", import.meta.url)` 部署后可能被 CDN 返回错误的 Content-Type，导致 Worker 加载失败。Desktop Chrome 对此宽容，所以 PC 正常。

**改动文件：**

| 文件 | 改动内容 |
|------|---------|
| `src/lib/file-parser.ts` | PDF.js Worker 改为通过 `public/` 加载（`.js` 扩展名确保正确 MIME 类型） |
| `public/pdf.worker.min.js` | 从 `pdfjs-dist/build/pdf.worker.min.mjs` 复制，重命名为 `.js` |
| `src/components/FileUpload.tsx` | 添加 120s 客户端超时控制，优化错误提示（区分超时 vs 其他错误） |
| `next.config.ts` | 添加 PDF Worker 的 Content-Type 响应头 |
| `eslint.config.mjs` | 忽略第三方 Worker 文件的 lint |
| `package.json` | 添加 `postinstall` 脚本，自动同步 Worker 文件 |

### 三个改进点

1. **PDF.js Worker MIME 类型修复** — Worker 文件复制到 `public/` 并用 `.js` 扩展名，确保所有浏览器（含移动端 Safari）都识别为 JavaScript
2. **客户端超时控制** — `fetch("/api/extract")` 添加 `AbortController` 120s 超时，防止慢速网络挂起
3. **错误诊断增强** — 控制台输出详细错误日志（文件名、大小、stack trace），区分超时错误给出友好提示

## 遇到的问题
- `pdfjs-dist` v6 移除了 `disableWorker` 选项，无法通过该参数禁用 Worker
- v6 源码内有 `#setupFakeWorker()` 回退机制，但在 `.mjs` MIME 类型错误时 `import()` 回退同样失败，因为模块加载也受 MIME 类型影响
